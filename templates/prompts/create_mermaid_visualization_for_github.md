# Create a Mermaid diagram

Visualize the concept, system, or process below as a Mermaid diagram that renders on GitHub.

## Steps

1. If the subject is code or a system in this repository, read the relevant files first and draw what the code does, not what you assume. If the input is a text description, work from it.
2. Pick the diagram type that fits: `flowchart` for processes and architecture, `sequenceDiagram` for interactions over time, `stateDiagram-v2` for lifecycles, `erDiagram` for data models, `classDiagram` for types, `gantt` for schedules, `mindmap` or `timeline` for concepts. Use features GitHub supports; skip experimental diagram types and features that may not render there (for example custom CSS or click handlers).
3. Keep it readable: roughly 5 to 25 nodes, short labels, one idea per diagram. If the subject is larger, show its main takeaway or split it into several diagrams.
4. Quote labels containing parentheses, brackets, colons, slashes or other special characters (`A["Label (v2)"]`), and use unique simple node ids.

## Output

- One fenced ```mermaid block, syntax-checked by eye. If the `mmdc` CLI is installed, validate with it.
- Below it, a short bullet list explaining how the diagram maps to the input, so the two can be checked against each other.
- If written to a file (for example a README), place it where the notes say.
