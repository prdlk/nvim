# Create a product requirements document

Turn the product idea below into a PRD that engineering and stakeholders can act on.

## Steps

1. If the idea extends an existing product or repository, read the relevant code and docs so requirements match what exists.
2. Identify the product concept, target users and the problem solved. Where critical details are missing, list them under Open questions instead of inventing them; use clearly marked placeholders for sample data.
3. Make each requirement specific, testable and unambiguous. Mark priority (must, should, could) and what belongs in the MVP.

## Output

Markdown with these sections:

- Overview: problem, product summary, background.
- Objectives and non-goals.
- Target audience: users and their needs.
- Features: with priority and MVP marking.
- User stories: with acceptance criteria.
- Functional requirements.
- Non-functional requirements: performance, security, accessibility, reliability.
- Technical considerations: integrations, dependencies, constraints.
- User experience considerations.
- Success metrics: measurable, with a target and how it is measured.
- Timeline and milestones: phases; mark dates unknown rather than guessing.
- Risks, assumptions and open questions.

Use tables and bullets where they aid reading.
